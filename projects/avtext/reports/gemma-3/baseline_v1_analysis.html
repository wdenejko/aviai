01 — Executive summary

Good at reading, bad at arithmetic

The base model extracts labelled scalars well but fails whenever a value must be transformed. Because two-thirds of the eval requires a unit conversion somewhere, that single weakness drags whole-record exactness to near zero.

  • Overall value accuracy 77.8% (hits / values that existed), whole-record EM 4%, hallucination 1.5%, JSON-valid 100%.
  • The dominant failure is unit conversion, uniform across every field that needs one: altimeter inHg→hPa 2%, wind m/s→kt 1%, visibility SM→m 71% — versus 94–95% on the same fields when no conversion is required.
  • Hallucination is low but non-zero — the model mostly respects “use null, don’t guess,” but occasionally fabricates (wind gust/direction, and masked /// wind groups).
  • Against the parser reference (97.5% / 0% / 82%), the base LLM is far behind on structured decode — as ADR-004 predicted — but the gap is one concrete, learnable skill.
Takeaway The model reads correctly and converts almost nothing. Fix conversion and whole-record accuracy should move from ~4% to ~30%+.
02 — Method

What was measured, and how

Each record is one raw METAR. The model is prompted (decode-json-v1) to emit a JSON decode in canonical units, with explicit permission to abstain — “use null; do NOT guess,” the line that makes a fabrication the model’s own fault rather than obedience. Its output is scored field-by-field against the reference: the 3-parser consensus, gold-calibrated against NOAA’s official decode at ~99.98% on altimeter. Scoring keeps the two ways of being wrong distinct:

Scoring taxonomy
ReferencePredictionOutcomeMeaning
value= valueHITcorrect
value≠ valueWRONGwrong value
valuenullABSTAINdeclined a knowable value — safe miss
nullvalueHALLUCINATEfabricated from nothing — dangerous
nullnullTRUE_ABSTAINcorrectly silent

Value accuracy = hits / values-that-existed; hallucination rate = fabrications / fields-truly-absent; EM = records with every value right and nothing fabricated. Intervals are record-level bootstrap.

04 — Finding 1

The model cannot convert units

This is the whole story. Split each conversion-bearing field by whether a conversion is required — the same field, read vs. transformed:

Altimeter
Q — hPa, read as-is · n=20495%
A — inHg, must convert · n=4162%
Wind speed
KT — read as-is · n=50675%
MPS — m/s → kt · n=1071%
Visibility
metric — read as-is · n=10894%
SM — statute mi → m · n=41571%

The pattern is unmistakable: when the value is already in the target unit, the model reads it; when arithmetic is required, it fails — most totally for the conversions far from 1:1 (inHg×33.86, m/s×1.94), least for statute-miles (a rounder, more likely-memorised mapping).

Concrete examples — verbatim, temp 0

RAW  : KSEA 280840Z AUTO 35005KT 10SM CLR 13/11 A2979 RMK T01300110
MODEL: altimeter_hpa=1013   (A2979 = 29.79 inHg = 1009 hPa)  → WRONG
       temperature_c=13 ✓   dewpoint_c=11 ✓   visibility_m=16100 ✓

The model emits 1013 — the ISA standard-pressure default — instead of converting. When it does attempt a conversion it can be wildly off (an A2993 case produced 1029, not the correct 1014).

RAW  : UUWW 090100Z 16005MPS 9999 SCT022 17/15 Q1005 R24/000062 NOSIG
MODEL: wind_speed=5   (16005MPS = 5 m/s = 10 kt)  → WRONG
       wind_dir=160 ✓   altimeter_hpa=1005 ✓ (Q-report, no conversion)
Why EM is pinned near zero EM requires every value correct. 147 of 620 records fail on altimeter alone — the model gets everything else right and only misses the inHg conversion. Fix that one skill and the EM ceiling rises from 4% to ~28%; fixing wind + visibility conversion lifts it further.

06 — Finding 3

Hallucination is low but real

1.5% overall — 11 fabrications: wind_gust (4), wind_dir (3), visibility (2), wind_speed (1), dewpoint (1). The model mostly abstains rather than invents, but it is not at zero (the 20-record smoke test’s 0% was an artifact). The sharpest case is a masked wind group:

RAW  : KJFK 172115Z AUTO ///18G24KT 10SM CLR 22/15 A3004 RMK T02200150
MODEL: wind_dir=180   (raw is `///` = direction unavailable; reference is null) → HALLUCINATE
       wind_speed=24  (should be 18 — it grabbed the gust)   altimeter=1013 (should 1017)

/// means the automated station could not determine wind direction — the honest answer is “unknown.” The model manufactured 180, almost certainly reading the 18 speed digits as a heading. This is the exact failure a safety-domain eval must catch, and holding it flat is a hard constraint on Phase 4: a finetune that lifts accuracy by learning to always-answer is a regression, not a win.

07 — Finding 4

Generalization, hard cases, robustness

  • Generalization is flat across axes. unseen_station clean 80.4% ≈ unseen_time clean 79.4% — no gain from station familiarity, a sanity check on the leak-free split.
  • Dissent cells (70–80%) sit near the clean cells — the model’s errors are dominated by conversion, orthogonal to the parser-disagreement that defines “dissent.”
  • parse_fail (73%) is telling: these UUWW m/s reports break a parser, yet the LLM reads them fine — it fails the m/s conversion, the same Finding-1 story, not a collapse. Tolerance of messy formats is a genuine (if modest) edge over the brittle parsers.
08 — Measurement integrity

Bugs found and fixed

“Your measurement code is part of the test” is the project’s refrain — so this section stays in the report. Preparing it triggered a two-part audit of the harness itself.

FIXED  Scoring path — 3 issues

  • Clouds-shape crash. The parser assumed clouds = [cover, base] pairs; the model sometimes emits dicts, and the KeyError scored the whole record invalid — even when temperature, altimeter, etc. were right. This alone was all 25 of the run’s “invalid” records; fixing it took JSON-valid 96% → 100% and lifted overall accuracy 75.1% → 77.8%. The conversion findings were unaffected — those are wrong values, not invalids.
  • Under-canonicalisation. _canon passed the model’s raw value through for wind ints, report-type case, and bools — a right-but-mistyped answer scored WRONG. Fixed to coerce every field. Audit: re-scoring saved predictions with vs without the fix flipped 0 outcomes — a no-op for this clean-JSON model, kept for robustness.
  • Div-by-zero on an empty eval — guarded (latent, never triggered).

CLEAN  Reference path — no bugs

Gold validated only the numeric fields; clouds, cavok, automated, report_type were never checked, and the last three are shared functions echoed across all parsers (illusory consensus). Adversarial review + empirical checks: conversions correct; automated/cavok matched an independent recompute 620/620; clouds decode hand-verified, adapters agree 99% (disagreements are same-base ordering), 0 references None; 0/620 degenerate; all 100 parse_fail references are 2-way cross-checked. The ground truth is trustworthy.

The direction is unambiguous: on clean structured decode the parser dominates, and even a strong finetune is unlikely to beat 200 lines of deterministic parser. The LLM’s durable advantage (per ADR-004) is the free-text/generative tail — NOTAM/SIGMET briefing — where no parser competes. The METAR finetune is the method being learned, not the destination.

11 — Threats to validity

What could bend these numbers

  • Reference circularity. The reference is parser-consensus, not human decode. Mitigated by the gold calibration; on dissent records the “correct” answer is the parser majority, a soft target.
  • report_type is near-vacuous. IEM data carries no METAR/SPECI keyword, so every reference is METAR and the 100% tells us nothing about capability. Ignore it as signal.
  • Cloud scoring is order-sensitive. Layers at the same base (FEW030 BKN030) have ambiguous order; the reference commits to one and dings the other valid reading — a slight downward bias on the 69%.
  • CAVOK → visibility is null. A model that emits 10000 for CAVOK scores as hallucinating. Defensible, but it penalises a reasonable interpretation on the handful of CAVOK records.
  • Single prompt. All results are for decode-json-v1. The prompt already says “convert m/s→kt, inHg→hPa,” so the failure reads as a capability gap — but a prompt ablation is worth doing before over-reading absolutes.
  • 4-bit quantisation & small cells. Served at MLX 4-bit (evaluate the finetune at the same quant); dissent cells are n=60 so per-cell CIs span ~7 points — treat them as directional.
