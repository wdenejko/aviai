## What changed

budget, confirming the shortfalls were caps and not availability:

All six are 100% redistributable (Apache-2.0 / MIT / ODC-BY). Persisted to the gitignored durable
zone `data/sft/`, not left in session scratch.

**Provenance defect found and repaired.** The acquisition driver wrote its manifest once per
source to the same path, so only the last source (`tulu3`) survived. The combined manifest was
rebuilt by scanning each pool's own record-level `meta` — the same field the assembler reads —
and written to `data/sft/gate2_breadth_manifest.json`.

### 2. Target C widened from 2 task families to 7

targetC is the one pool a teacher must generate, and it needs ~160 more trajectories. Reaching
that from the existing two templates would have meant ~110 repetitions of each, which teaches
those two task formats rather than ML-delivery discipline. Five families were added, each aimed at
a **different** delivery failure mode:

| task | teaches | metric |
|---|---|---|
| `mlc_widget_defect` | balanced classification (existing) | ROC-AUC ≥ 0.65 |
| `mlc_delivery_time` | regression vs a baseline (existing) | MAE, +6% vs median |
| `mlc_churn_rare` | ranking under a ~8% base rate | AP ≥ 0.15 |
| `mlc_energy_load` | a temporal train/test boundary | MAE, +25% vs carry-forward |
| `mlc_ticket_route` | multiclass, categorical deliverable | macro-F1 ≥ 0.50 |
| `mlc_credit_leak` | refusing a post-outcome feature | ROC-AUC ≥ 0.70 |
| `mlc_upsell_join` | aggregating a second table first | ROC-AUC ≥ 0.70 |

### 3. Tasks are now gated in both directions

One-shot validation missed real bugs in **both** directions, so the gate was split in two.

**Solvable** (`ml_tasks --reps N`) — the reference must clear the bar across N datasets, not one.
`mlc_ticket_route` failed its own oracle on **5 of 8 seeds** while passing the base seed by 0.010.
Worst-case over 10 seeds after retuning:

```
PASS mlc_widget_defect  min 0.898   PASS mlc_ticket_route  min 0.816
PASS mlc_delivery_time  min 5.030   PASS mlc_credit_leak   min 0.823
PASS mlc_churn_rare     min 0.169   PASS mlc_upsell_join   min 0.882
PASS mlc_energy_load    min 3.100
```

**Failable** (`ml_task_controls`) — the careless approach must lose, or a kept trajectory proves
nothing. This caught the leakage trap being decorative: with an imperfect leak (label AND a 90%
coin) a model trained on every column still scored **0.814**, because the `flag=0` node stayed
impure and the trees learned the honest features underneath it. With an exact leak the leaky model
collapses to **0.501** while the honest reference holds at **0.823**. All seven controls now fail
as intended.

A unit test (`test_ticket_uses_every_queue`) then caught the retune starving the `account` queue to
1.5% of rows — a cap on macro-F1 no matter how good the model is. Rebalancing the intercepts lifted
worst-case macro-F1 from 0.705 to 0.816.
